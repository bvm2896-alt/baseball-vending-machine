시리즈는 셋, 채널은 하나(야구자판기), 프로그램도 하나.
- **야구순위**: 순위·경우의 수·예측 (`episodes\YYYY-MM-DD_순위.json`, 폴더 `야구순위\`, railTitle "KBO 순위", 다크 템플릿 `template.html`, 썸네일 `thumb.html`)
- **야구이슈**: 그 외 야구 이야기 (`_이슈.json`, `야구이슈\`, "KBO 이슈", 화이트 템플릿 `template_issue.html`, **썸네일 `thumb_issue.html`(사진형)**)
- **야구분석**(9/15 신설): 한 팀·한 현상의 원인 분석 (`_분석.json`, `야구분석\`, "KBO 분석", 팀 색 템플릿 `template_analysis.html` + 로고 썸네일 `thumb_analysis.html`)
같은 날 여러 편은 `_순위2`, `_이슈2`… 번호를 붙인다. **하루 배치는 순위 1 + 이슈 2~3 + 분석 0~1**(9/16 밤 분석 데이터 반영 — 순위 편을 여러 개 내면 서로 잡아먹는다. 아래 §14). 한 채팅에서 세 시리즈를 다 한다. **아시안게임 기간(9/19~10/초)은 이슈 = 아시안게임 2편 + 순위 1편**(9/22 사용자 지시).

## 0. 절대 금지 (사고에서 나온 것)
- 회사 계정(samsungheehee) 으로 채널 작업 금지. 새 구글 계정 만들지 않는다. 로그인·비밀번호 입력은 사용자가 한다.
- **유튜브 API 로 업로드하지 않는다**(9/11 정지 사고). 업로드는 사용자가 유튜브 스튜디오에서 손으로. 영상 삭제·재업로드 금지, 비공개 올려서 검수 금지. 제목·설명만 바꿀 땐 스튜디오에서 수정(재업로드 X). (예외: 올리는 날 기준으로 틀린 내용이면 삭제 — 사용자가 정한다.)
- `설정.txt`·`client_secret.json`·`token.json` 은 열지도, 고치지도, 채팅에 붙이지도 않는다. 깃 원격 주소에 토큰이 들어 있으니 원격 URL 을 출력하지 않는다.
- 클라우드(Cowork 컨테이너)에서는 절대 push 하지 않는다. 파일은 device_commit_files 로 PC 에 넣고, PC 의 `깃저장.cmd` 가 push 한다.
- **클라우드에서 mp4 를 만들지 않는다(9/21).** 콘티·음성 zip·사진·템플릿만 PC 에 넣고 제작은 PC 의 cmd 가 한다. 클라우드는 prep 검사·미리보기까지.
- 파일 다운로드(타입캐스트 zip 등)는 사용자 허락 뒤에. 워터마크 사진은 쓰지 않고 지우지도 않는다(**잘라내서 쓰지도 않는다** — 9/17).
- **사람 사진은 이름이 캡션·기사에 그 사진과 직접 붙어 있을 때만 쓴다(9/21 최지만 사고).** 캡션 순서·유니폼·추정으로 이름을 붙이지 않는다. 확신이 없으면 사진을 빼고 이름 카드로. 사진을 쓴 편은 업로드 전에 **한 명씩 팩트체크**한다(사용자 "다른 사진도 다 팩트체크해").
- **사진이 일부만 있으면 섞지 않고 하나로 통일한다(9/21).** 예: 구단별 드래프트 편은 1라운더만 사진, 나머지 전원은 이름 카드.
- 스톱 훅의 "Unverified commits" 경고는 서명 문제일 뿐 → 무시.
- 썸네일은 **영상 폴더에만**. 따로 `썸네일\` 폴더를 만들지 않는다(9/15).
- 음성 zip 은 반드시 `야구자판기\<시리즈>\음성\`(시스템\ 밖).
- **사용자 환경 상태를 바꾸는 조작(브라우저 계정 전환, 채널 설정 저장 등)은 먼저 말하고 한다(9/16 사용자 지시 "말을 좀 하고 해").** 채널 설정은 입력해서 검증만 보고, 게시는 사용자 확인을 받고 누른다(9/17).
- **이미 만들어진 결과물(썸네일·mp4)을 덮어쓰기 전에 그 시리즈의 템플릿이 다 있는지 확인한다(9/17 사고).** 아래 §11 참고.

## 2. 하루 작업 순서 (밤)
1. 경기 종료 확인 → 다음스포츠 일정(`sports.daum.net/schedule/kbo?date=YYYYMMDD`)·순위(`sports.daum.net/record/kbo/team`)·투수 기록·뉴스(`search.daum.net/search?w=news&q=…&sort=recency` → `v.daum.net` 기사)로 팩트 수집. 내장 브라우저에서 `get_page_text` 나 JS `innerText` 로 읽는다(네이버 스포츠는 차단).
2. 주제 후보를 시리즈별로 제안 → 사용자가 고른다.
3. **사진 먼저**: 필요한 사진 목록을 정하고 Claude 가 직접 저장(§6). 인용이 있는 편은 **보도 카드**까지 이때 만든다.
4. 콘티 작성(§3~5) → `python -X utf8 build.py prep episodes\<파일>` 통과 → **검수**(§4) → 미리보기 렌더로 화면 확인(§7).
5. 콘티 JSON 을 PC `시스템\episodes\` 에 넣는다.
6. 음성: 타입캐스트 웹에서 장운 zip(§8) → `야구자판기\<시리즈>\음성\<콘티이름>.zip`.
7. 사용자가 시리즈별 **지금실행** → 영상 나오면 프레임 검수(§9) → 고칠 게 있으면 한 줄 교체 → 다시 지금실행.
8. 아침 업로드(사용자): mp4 + `_유튜브.txt` + `_자막.srt`. 업로드 시간은 07:30 / 12:00 / 20:30 으로 벌린다(한꺼번에 올리면 서로 노출을 나눠 먹는다 — 9/14에 4편 몰아 올린 날 하나가 31회).
   - (9/17 스튜디오 실측) 시청자 이용 시간대는 **오후 4~8시가 전 요일 통틀어 가장 진하고**(특히 월요일 저녁), 주말은 오전 10시~오후 2시도 진하다. 새벽~오전 6시가 가장 옅다.
   - (9/22 실측) 같은 검색어를 노리는 편이 여러 개면 서로 죽이지만, **구단별 편처럼 검색어가 다 다른 시리즈는 10편을 하루에 올려도 전부 살았다**(480~3,818회). 겹치느냐가 문제지 개수가 문제가 아니다.
9. 끝나면 메모리와 프로젝트 문서에 바뀐 규칙을 적는다.

## 3. 콘티 JSON 형식
```
{ "date": "2026-09-17", "gameDate": "2026-09-16", "series": "야구순위", "railTitle": "KBO 순위", "focusTeam": "KT",
  "source": "근거 기사·수치·계산·사진 출처를 한 줄씩(나중에 정정할 때 본다)",
  "thumb": {...}, "youtube": {...}, "lines": [{ "narr": "...", "sub": "..." }, ...], "scenes": [...] }
```
- `lines[].narr`: 나레이션. 호흡마다 ` / `. `lines[].sub`: 자막, `|` 로 **호흡 수와 똑같이** 나누고 `\n` 으로 줄바꿈. 줄 하나 = 장면 하나(scenes 의 `startLine`).
- 장면 종류(세 템플릿 공통): `hook`(teams, img, text, size) / `big`(text, team|img, num, numLabel, note, size) / `table`(highlight) / `versus`·`need`(left/right: {team|name|img, value, label, next, nextNote, mark}, num) / `matchup`(left, right 팀 **또는 나라**, text, img, vsText, score, tag, stats[{k,v}]) / `wins`(rows[{team,total,need,label}]) / `schedule`(title, items[{date,teams,place,tbd}]) / `photo`(img, team, tag, text, size, fit, h) / `people`(title, items[{img,name,team,note,bad}]) / `teamgrid`(items[{team,value,label,bad}]) / `steps`(items[{date,text,sub,hi}]) / **`cards`(items[{badge,name,sub,hi}] — 4장이면 2×2 폭 470, 3장이면 한 줄 폭 330(이름 4자 이내); 사진 없는 인물 목록용, 9/21)** / **`roster`(투수/야수 두 칸 이름 나열, 9/21)** / `verdict`(label, big, left, right, img — left/right 는 **팀 이름만**) / `question`(text) / streaks·shift·rival.
  - `matchup` 의 `left/right` 에 나라 이름을 주면 국기를 그린다 — `template_issue.html` FLAG: 한국·대만·일본·태국·홍콩·**중국·필리핀·팔레스타인(9/22 밤 추가, 9/23 회사 PC 커밋 완료; 집 PC 는 깃가져오기 필요)**. `vsText` 는 가운데 "VS" 자리에 대신 넣는 글(경기 시각·"5회 콜드"), `score` 는 점수, `stats` 는 아래 작은 카드.
  - **`verdict` 에 팀 없이 `img` 만 넣으면 화면이 깨져 보인다(9/17).** 팀이 없는 편(고교·국가대표 등)은 `photo` 에 `tag:"제 예상"` 을 붙여 쓴다.
- 옵션: `num` 번호 배지(숫자만). **글자를 붙일 땐 `numLabel`**("변수 1"). `next` 는 상대 하나(문자열) 또는 **여러 팀 배열**. 카드 `label`·people `note`·versus `label` 은 `\n` 으로 줄을 직접 나눈다.
  - **배지 모양(9/17)**: `numLabel` 이 있거나 숫자가 **세 자리 이상**이면 동그라미가 아니라 **알약 배지**로 그린다(104px 원에 세 자리를 넣으면 숫자가 삐져나온다). `template.html`·`template_issue.html` 에 적용 완료. `template_analysis.html` 은 원래부터 알약("이유 N")이라 손댈 것이 없다.
- `img` 는 파일명(확장자 없이). 찾는 순서: `선수이미지\` 루트 → `KBO프로필\` → `국가대표프로필\` → `고등학교\` → `상황별\` → 그 외 하위 폴더, 그리고 `<시리즈>\재료\사진\<콘티이름>\`. `"상황별/울산웨일즈_1위"` 처럼 폴더 지정 가능. 없으면 템플릿이 로고/큰 글씨로 대신하지만 **없는 채로 내보내지 않는다**.
- `thumb`: **순위** `{teams:[A,B], top, big, layout:"clash", color}` / **이슈** `{teams:[구단], img, top, big, fit, focus, logos:false, color}` / **분석** `{teams:[구단], top, big}`. top 은 짧게(분석 알약 폭 840px). 따옴표 금지.
  - 이슈는 **`img` 가 반드시 있어야** 사진형이 제 모습이 된다(비우면 깨진 아이콘이 나간다 — 9/22 사고). `logos:false` 는 사진 위 좌우 로고 칩을 없앤다 — 드래프트 전 선수처럼 구단을 단정할 수 없을 때 쓴다(9/17 하현승 편 다섯 개). **`focus`** 는 사진 잘라내는 기준점(object-position, 기본 "50% 12%") — 얼굴이 아래쪽이면 "50% 42%" 처럼 올린다(9/22 홍콩 투수).
  - **썸네일 메인 텍스트(`big`)에 그 편 주인공 이름을 넣는다(9/17 지시).** `top`(작은 윗줄)이 아니라 강조색 큰 글씨 쪽이다. 예: `big: "하현승 피지컬\n사회인야구 수준"`. `top` 과 `big` 에 **같은 낱말을 두 번 넣지 않는다**("아시안게임 태국전 / 태국전 소형준" ✗ — 9/22). "몇 회 콜드" 같은 열린 말은 **물음표**를 붙인다.
  - **구단별 시리즈는 `color` 를 그 구단 키컬러로(9/21 지시).** 팀 색 표는 §6 끝.
- `youtube`: title / description / tags / hashtags (§10).
- `done: true` 는 §1 참고.

## 4. 나레이션·콘티 작성 규칙
- 한 호흡(` / ` 사이) **12자 안팎, 20자 초과 금지**(공백 제외). 훅은 한 호흡 25자 이내, 직관적·자극적. 순위 편 13~17줄, 이슈·분석 13~15줄(구단별 시리즈 12줄, 아시안게임 편 13줄).
- **숫자 읽기 원칙(9/23 사용자 "매직넘버 11은 십일, 십일 승을 열한 승이라 하지 마")**: 매직넘버·승·패·위·회·이닝은 한자어("매직넘버 십일이에요", "십일 승만 더 하면", "사 승 일 패면"), 경기 수·게임 차·명·개·횟수는 고유어. "열한 번 이기면"처럼 승수를 고유어로 쓰지 않는다. `subdigits.py` 가 "매직넘버 십일이에요"→"매직넘버 11이에요" 로 자막을 만든다.
- 숫자 읽기: 고유어(점·경기·게임 차·개·명·시·가지·번 — "세 점", "**열다섯 점 차**", "세 게임 차", "여든다섯 개") / 한자어(승·패·위·이닝·회·년·월·일·억·달러·순위·연승·점수·대 — "십삼 대 삼", "육 이닝", "칠 연승", "오 회 콜드"). **점수를 "십오 대 영" 으로 읽는 건 한자어지만, "열다섯 점"처럼 점을 세면 고유어**(9/22 prep 경고). 소수점은 "삼 점 팔팔". 영어 팀명은 한글(케이티/엘지/기아/엔씨/에스에스지/케이비오). 어미 ~에요/~인데요/~거든요, "입니다" 금지, 콤마·마침표 금지(물음표 하나만). 반올림 금지.
- **자막 = 나레이션 그대로(9/22 밤 사용자 지시 "자막은 왜 나레이션대로 안 나와? 앞으로 모든 영상에서도 마찬가지")**. 요약 자막 금지. 호흡(` / `)마다 자막 하나, 숫자 읽기만 아라비아 숫자로 바꾼다(`tools/subdigits.py`: "십삼 대 영"→"13-0", "열다섯 점"→"15점", "케이비오"→"KBO", "에이조"→"A조"; "한 번"·"이 대회"·"이 경기" 같은 건 그대로). 16자 넘으면 가운데 띄어쓰기(조사 뒤 우선)에서 두 줄. 생성기 `L(narr)` 이 자동으로 만든다 — sub 를 손으로 쓰지 않는다. **화면 숫자 = 나레이션 숫자**(9/16).
- **기승전결(9/22 밤 "콘티가 뜬금없는 이야기를 자꾸 내보낸다")**: 줄마다 앞 줄에서 이어지는 이유가 있어야 한다. "이게 왜 한국 얘기냐면" 같은 급전환 금지 — 먼저 틀을 설명하고(조 편성 → 슈퍼라운드 → 그래서 이 경기) 본론으로. **처음 보는 사람 기준**: 한국이 안 나오는 경기·다른 조 얘기는 반드시 "아시안게임 야구는 여덟 나라가 두 조로 나뉘어요 / 한국은 B조 일본은 A조예요" + "각 조 1·2위가 슈퍼라운드" 한두 줄을 앞에 둔다(`groups()`·`superround()` 장면). 아는 사람만 아는 말투 금지.
- **"제 생각/제 예상"과 마지막 양자택일이 충돌하면 안 된다(9/22 밤)**: "불펜 점검이 급했다"고 해 놓고 "2이닝 교체 맞았을까요?"라고 묻지 않는다. 질문은 예상 다음 단계(일본전도 무실점일까?)로.
- **숫자 하나만 던지는 압축 표현 금지(9/22 밤 "홍콩 주자 0명이 너무 불친절해")**: "홍콩 주자 0명" → "홍콩 타자 21명 전부 아웃"처럼 무슨 일이 있었는지가 문장 안에 있어야 한다. 썸네일 `big` 도 같다.
- 처음 보는 사람 기준: 용어는 나올 때 한 줄 설명(단판·매직넘버·퀄리티스타트·가을야구 5위·사회인야구·콜드게임·슈퍼라운드) + `big` 장면으로 뜻을 같이. 변수는 "무엇에 대한 변수"를 먼저. 예측은 대상 명시. 한 편 한 줄기, 화제 전환엔 브릿지 문장, 사건은 인과 순서.
- **빠진 선수는 조용히 빼지 않는다(9/16)**: 세다가 시청자가 "왜 ○○는?" 할 선수가 있으면 한 줄 설명을 넣는다.
- **"단(뒤집힐 조건)"은 당연한 말 금지(9/16)**: 주인공의 약점에서 나오는 구체 조건으로.
- **같은 카드·같은 값이 반복되는 장면 금지(9/16 밤)**: teamgrid 세 칸에 같은 말("거포 필요")을 넣지 말고 팀마다 다른 숫자를 넣는다.
- 마지막 질문은 **양자택일**, 의견이 갈리는 질문, 시비조 금지. **두 선택지가 실제로 대립해야 한다** — "몸일까요 / 하현승일까요?" 처럼 대립이 안 되는 짝은 버린다(9/17). 실제 올라간 이전 편만 "전 편에서"로 이어 말한다.
- **엔딩(9/23 새벽 개정 — 모든 편, 모든 시리즈)**: 마지막 줄 = `"<양자택일 질문> / 채널 구독하고 매일 야구 이슈 받아보세요"` (사용자 지시 "앞으로 모든 영상의 마지막 멘트는 질문을 한 뒤 … 채널 구독하고 매일 야구 이슈 받아보세요!"). 자막은 생성기가 이 호흡에만 `!` 를 붙인다. 이전 엔딩("채널에 다른 경기 편도 있어요", 다음 편 예고)은 **더 쓰지 않는다**. 이 호흡이 나가는 동안 화면에 **구독 버튼 화살표**가 뜬다(§6·§11) — 나레이션에 "구독" 이 들어 있으면 템플릿이 자동으로 켠다.
- **화면 큰 글씨는 그 장면만 떼어 봐도 뜻이 통해야 한다(9/18 사용자 지적 "아무리 들어도 이해가 안 돼").**
  - **지시어(그·저·이)로 앞 내용을 가리키는 압축 요약 금지.** 나쁜 예: `말보다 / 그 질문이 무섭다` — 누구 말인지, 무슨 질문인지, 누가 누구에게 무서운지가 다 빠져 있다. 좋은 예: `약점 들으면 / 바로 묻는다`.
  - **지시어는 바로 앞 줄만 가리킨다.** 두 줄 이상 건너뛴 "그걸"은 시청자가 되짚어야 하고 거기서 빠진다.
  - 문장에 **주어와 대상**이 있는지 본다. "무섭다·대단하다·다르다" 같은 말은 누가 누구에게인지가 없으면 뜻이 안 선다.
- **"제 예상은" 줄은 누가 · 무엇을 · 앞으로 어떻게 될지를 다 말한다.** 감상이나 성격 묘사로 끝내지 않는다.
- **검수(필수, 음성 뽑기 전)**: 한 줄씩 (1) 앞 줄과 인과 (2) "더 크다·셋 다" 의 대상이 문장 안에 있는지 (3) 사실 논리 (4) "유일·최초·최장" 같은 단정은 근거 두 곳 (5) 반대 근거 한 번 더 검색 (6) **화면 큰 글씨만 소리 내어 읽어 보고 그 자체로 뜻이 통하는지**(9/18 신설) (7) **사람 사진마다 이름이 그 사진에 직접 붙어 있는 출처가 있는지**(9/21 신설) (8) **마지막 질문이 "제 예상" 과 충돌하지 않는지, 엔딩 문구가 §4 형식인지**(9/23). **한 기사 안에서 제목과 본문이 엇갈리면 그 사실은 쓰지 않는다(9/16 밤).** 기사마다 다른 값(나이 35/36, 키 194/195, 경기 시각 12시/14시 등)은 두 곳 이상 일치하는 값만 쓴다. **출처가 한 곳뿐인 수치는 아예 빼고, 두 곳에서 확인되는 인용·기록으로 대체한다(9/17).**
  - **"작년/재작년" 같은 시점어는 실제 연도를 확인하고 쓴다(9/17 사고).**
  - **한국 매체가 외신을 인용한 대목은 원문을 직접 확인한다(9/17).** 야후 재팬·대만 매체는 WebFetch 가 robots.txt 로 막히니 크롬으로 열어 `get_page_text` 로 읽는다. 표기도 원문 기준으로 — 장이안은 **張乙安**(張奕安 아님).
  - **아직 발표되지 않은 것(선발 투수 등)은 "유력"까지만** 쓰고 확정처럼 쓰지 않는다(9/22 태국전 소형준).
- 팩트 출처: 순위·기록은 KBO 공식/다음스포츠, 뉴스는 다음 뉴스(최근 1일), 기사 날짜 이후 경기까지 검증. 모든 숫자에 출처 두 곳. 클라우드 WebFetch 가 되는 곳: 이투데이·아주경제·위키트리·udn(대만)·bankeela(태국)·focustaiwan·tiebreakertimes(필리핀)·japan-baseball.jp(일본 사회인야구 공식). 막히는 곳: 네이트·올림픽스·KBO 공식·엑스포츠뉴스·야후·인스타 → 크롬.

## 5. 시리즈별 전개 틀
- **순위**: 훅 → 그날 결과·현재 순위(`table`) → 남은 경기 → 용어(매직넘버 등, big) → 경우의 수를 숫자로 닫기(`wins`) → "변수는 두 가지" → 변수 1 → 변수 2(맞대결 `schedule`) → "그래서 제 N위 예측은"(`verdict`) → 단(주인공 약점 조건) → 양자택일.
  - **9/16 밤부터 순위는 하루 1편, 1위 싸움 하나만 다룬다.** 3위·5위 싸움을 따로 내면 제목이 겹쳐 서로를 죽인다(실측: 같은 제목 3연속 → 75회·31회). 5위 싸움 같은 건 이슈 편에서 인물 중심으로 푼다.
- **이슈**: 훅(무슨 일) → 사실(언제·누가·숫자) → 왜 중요한가 → 맥락·전례 → 전력·발언 근거(인물 사진·**보도 카드**) → 상대 사정 → "제 예상은" → 양자택일 + 구독 멘트. 순위표·필요 승수·승률 계산은 넣지 않는다(순위 편의 몫). 해외 반응·앞으로 일어날 일 각도를 섞는다.
  - **경기 미리보기 편(9/22 태국전)**: 훅(시각 + 관전 포인트) → 상대 최근 결과 두 경기(`matchup` 국기) → 규정 한 줄(콜드·슈퍼라운드) → 전례(`matchup`) → 우리 쪽 선발·백업(`big`/`photo`) → 왜 중요한가 → "제 예상은"(`matchup` vsText) → 양자택일.
  - **아시안게임 편(9/22~)**: 지난 경기 = 리뷰 + 각국 반응(+왜) / 예정 경기 = 전력 비교 + 반응 + 예상(상대가 확정된 경기만). 한국이 안 나오는 경기는 `groups()` → `superround()` → "그래서 이 경기가 한국에 중요" 순으로 연다. 생성기 `tools/gen_ag_0922.py`.
- **분석**: 훅(결과 대비) → 결과 한 장면(`versus`) → "이유는 세 가지" → 이유 1·2·3(`big num+numLabel`) → 반대 요소 → 정리 → 앞으로 → 양자택일.
- **한 인물 시리즈(9/17 하현승 5편)**: 편마다 각도를 완전히 다르게 잡고(피지컬 / 상대국 반응 / 본인 선택 / 갈 팀 / 전례). 썸네일 색도 편마다 바꿔 목록에서 구분되게(#22D3EE·#FB923C 등).
- **구단별 시리즈(9/21 드래프트 10편)**: 12줄 고정 틀 — 훅(1라운더 사진) → 1R 한 줄 → 2R~ 을 `cards` 3~4장씩 → 특이 지명 한 줄 → `roster` 총정리 → 평가 한 줄 → 엔딩(§4). 생성기 `tools/gen_draft_teams.py` + `data/draft2027.json`. 한 사람이 한 편에서 두 번 나오지 않게.
- 선수·구단 편중 금지(같은 선수·구단 하루 최대 2편 주인공). 순위·이슈 팀 조합이 겹치지 않게.

## 6. 화면·사진 규칙
- **자막 위는 텍스트보다 이미지가 먼저다 — 모든 시리즈, 모든 편(9/17 3차 지시).** 장면을 짤 때 먼저 "여기 넣을 그림이 뭔가"를 묻고, 정말 없다 싶을 때만 글자만 쓴다. 예외로 **실제로 누가 한 말을 글자로 띄우는 건 괜찮다**(인용 자체가 그림 역할을 한다). 용어 뜻풀이(`사회인야구 = 어른 동호회 야구`)처럼 그림이 없는 개념도 글자만 허용.
- **썸네일은 실제 사진으로 만든다 — 국기·로고만 넣은 썸네일 금지(9/22 밤 사용자 "썸네일이 아니라 국기만 넣어놨잖아").** `상황별/매치_<A>_<B>.jpg`(국기 두 개) 는 사진을 못 구했을 때 본문 `matchup` 대용일 뿐 썸네일엔 쓰지 않는다. 사진이 없으면 **먼저 구하고**(§6 가져오는 법), 그래도 없으면 사용자에게 말한다. 국제 대회 상대국 사진은 그 나라 협회 공식 사이트(예: 일본 `japan-baseball.jp` 대회 페이지, 워터마크 없음)에서 — 이름이 안 붙은 사진은 **이름을 쓰지 않는 장면·썸네일에만**.
- **구독 화살표 9/23 오후 최종(현행)**: 구독 버튼 **바로 위에서 아래를 가리킨다**(사용자 "휴대폰 기종마다 다르게 보일 수 있지? → 오른쪽 말고 위에서 아래로"). 기종마다 버튼이 좌우로 밀려도 아래 방향이라 덜 어긋난다. 위치 left 475·top 1430, 96×116(버튼 중심 x523, 화살표 끝 y1542~1554). 9/23 저녁 두 번째 아이폰 캡처(설명 한 줄짜리)에서 버튼이 영상 y≈1626 까지 올라와 1차 위치(끝 1645)는 버튼에 박혔다 → 올렸다가 "너무 올렸다 살짝만" → 이 값으로 확정("화살표 위치 좋아"). 짧은 화면 폰도 고려해 버튼과 간격을 둔다. 화살표가 뜨는 동안 자막 top 1220. 디자인 C블루: 하늘색→파랑 그라데이션(#6EE7F9→#3B6BFF)+흰 테두리 6px+그림자. 움직임은 CSS 애니메이션 금지 — `drawSub` 에서 영상 시간 t 로 계산(위에서 0.35초 내려오며 등장, 1.6초 주기로 12px 아래로 천천히 왕복, 깜빡임 없음), '구독' 자막 시작부터 영상 끝까지 유지. 이전 판(빨간 아래 화살표·오른쪽 옆 화살표)은 폐기.

## 11-3. 롱폼 (야구롱폼) — 2026-09-18 신설

**구조: 롱폼을 먼저 만들고, 그 콘티의 챕터를 잘라 쇼츠로 낸다**(사용자 결정).

- **롱폼 = 가로 1920×1080** (`template_long.html`), **쇼츠 = 세로 1080×1920**. 썸네일은 롱폼만 **가로 1280×720**(`thumb_long.html`).
- **길이는 6~8분.** 하한은 3분 초과(3분 이하는 쇼츠로 분류).
- 콘티: `episodes/YYYY-MM-DD_롱폼.json`, `series: "야구롱폼"`, `railTitle: "KBO 깊게"`. 결과물은 `야구자판기\야구롱폼\영상\<경기날짜>\`.
- **`chapters`** 배열: `{"key","title","from","to","short":{"slot","date","thumb","youtube","focusTeam"}}`. `from`/`to` 는 줄 번호. 새 장면 타입 **`chapter`**(쇼츠로 자를 때 `hook` 으로). 레일에 `2/5 대만 반응` 칩 + 진행 바, 설명란 챕터 타임스탬프 자동.
- **대본은 챕터마다 훅 1줄로 시작.** 롱폼 대본 = 인트로 3줄 + (훅 1줄 + 본문 13~14줄) × 5 + 아웃트로 ≈ 80줄.
- **음성은 롱폼에서 한 번만 뽑는다.** `build.py cut` 이 줄별 mp3 를 쇼츠로 재배치.

### 롱폼 품질 기준 — 쇼츠보다 훨씬 빡세게 (9/18 사용자 지시)
> "시청자를 붙잡아두려면 진짜 재미있는 주제뿐만 아니라 영상 퀄리티도 굉장히 좋아야 하고 뭐 하나 버벅거리는 부분이 없어야 돼. 이미지와 나레이션과 자막도 실수 없이 고퀄리티로. 신경 좀 많이 쓰고 여러 번 검수하는 과정을 좀 가지면 좋겠어."

**롱폼은 네 번 검수하고, 한 번이라도 걸리면 고친 뒤 처음부터 다시 본다.**
- **1차 — 대본**: §4 검수 전부. 챕터 첫 줄이 훅인지, 챕터 사이 연결 문장, 반복 표현.
- **2차 — 화면**: 모든 장면 미리보기. 같은 사진은 롱폼 전체에서 두 번까지. 글자만 있는 장면 두 개 연속 금지, 챕터 첫 장면은 이미지. 가로 자막 한 줄 24자.
- **3차 — 프레임**: fps=1 전부 + 챕터 전환 앞뒤 2초는 1초 4장.
- **4차 — 소리**: 음량·발음·쉼·싱크(특히 챕터 경계).
**한 번이라도 고쳤으면 2차부터 다시.**

### 명령
```
python -X utf8 build.py prep   episodes/2026-09-22_롱폼.json
python -X utf8 build.py render episodes/2026-09-22_롱폼.json
python -X utf8 build.py cutall episodes/2026-09-22_롱폼.json
python -X utf8 build.py cut    episodes/2026-09-22_롱폼.json 2
```
### 만든 것 (9/18)
- `template_long.html`(왼쪽 비주얼 / 오른쪽 큰 글씨, 사진 높이 상한 648) · `thumb_long.html`(big 두 줄, 한 줄 7자) · `frames.js`·`thumb.js` 환경변수 `FRAME_W/FRAME_H`, `THUMB_W/THUMB_H` · `build.py` `is_long()`·`cut_chapter()`·`cut`·`cutall` · `episodes/_샘플_롱폼.json`(레이아웃 확인용). run_daily 는 아직 롱폼을 모른다. **롱폼 템플릿에는 아직 `#subhint` 가 없다**(가로 화면이라 버튼 위치가 다름 — 필요하면 따로).
