# 야구자판기 — Claude Code 작업 지침

이 폴더(`시스템\`)는 KBO 순위 쇼츠를 매일 자동으로 만드는 파이프라인이다. 사용자는 개발자가 아니다.
설명은 한국어로, 짧고 구체적으로. 코드 변경은 반드시 이 파일의 규칙을 지킨다.

## 문서 유지 (9/16 사용자 지시 — 시키지 않아도 한다)
- 새 규칙·피드백·사고가 생기면 **그 턴에** ① 이 파일 ② 프로젝트 문서 `claude/야구자판기-공통규칙.md`(해당 절, 날짜 표시) ③ 메모리 `kbo-shorts-updates.md` 를 같이 갱신한다. 작업 단계가 끝날 때마다 `claude/kbo-shorts-작업현황.md` 도 고친다. 새 채팅은 공통규칙 → 작업현황 → 메모리 순으로 읽고 시작한다.

## 폴더
- `episodes\YYYY-MM-DD_순위.json`(야구순위 시리즈) / `YYYY-MM-DD_이슈.json`(야구이슈 시리즈) / `YYYY-MM-DD_분석.json`(야구분석 시리즈, 9/15 신설 — 한 팀·한 현상의 원인 분석, `--series analysis`, 폴더 `야구분석\`, 전용 템플릿 `template_analysis.html`(위 340px 팀 색 띠 + 종이색 바탕 + 팀 색 윗줄 카드, 번호 배지는 동그라미 대신 "이유 N" 라벨 — 장면 `num`·`numLabel`), 썸네일은 `thumb_analysis.html` — 바탕 전체 구단 색 + **구단 로고 화면 가득**(항상, img 안 씀) + 흰 큰 글씨, 키컬러 = focusTeam 구단색, railTitle "KBO 분석", #야구분석. 수치가 많으니 모든 숫자에 출처 두 곳 + 반대 근거 확인). 옛 이름 `_1`·`_2` 도 읽힌다. `{"draft": true}` 만 있으면 아직 미완성 → run_daily 는 계속 기다린다. 콘티 `series` 항목("야구순위"/"야구이슈")이 결과물 폴더를 정한다.
- `work\voice_<콘티이름>\NN.mp3 / NN.segs.json / NN.txt / qa.json` 편별 음성·검수 결과. `work\current.txt` = 지금 쓰는 편.
- `data\rank_latest.json`(네이버 순위) · `news_latest.json`(구글 뉴스) · `schedule_latest.json`(네이버 일정·선발)
- 결과물: `설정.txt` 의 `OUTPUT_DIR`(집 PC: `H:\내 드라이브\야구자판기_영상확인`) 아래 `YYYY-MM-DD\번호_팀.mp4 + _썸네일.jpg + _유튜브.txt`. 날짜 폴더 = **경기 날짜**(밤 제작이면 그날, 아침 제작이면 어제).
- 상위 폴더 `야구자판기\` : 공용(`시스템\`, `폰트\`, `KBO_logos\`, `브랜드\`, 전체 실행 cmd, `오늘.txt`) + 시리즈 폴더 `야구순위\`, `야구이슈\`(각각 전용 `지금실행.cmd`·`영상만다시.cmd`, 그 시리즈의 `오늘.txt`·신호 파일·`영상\날짜\`·`메모\`). **시리즈 폴더의 지금실행은 그 시리즈 콘티만 만든다**(`run_daily.py --series rank|issue`). 루트의 지금실행은 둘 다.
- `설정.txt`, `client_secret.json`, `token.json`, `work\`, `data\`, 영상은 git 에 올리지 않는다(.gitignore). 절대 채팅·커밋에 노출 금지.

## 실행 흐름 (run_daily.py)
git pull → fetch_rank.js → fetch_news.js → fetch_schedule.js → 오늘 콘티 대기(최대 45분) → `build.py prep` → `tts.py` → `qa_voice.py`(검수·재합성·자막 구간) → `build.py render`(frames.js 2K 60fps) → OUTPUT_DIR 저장 → 신호 감시(업로드.txt/공개.txt/재생성.txt/종료.txt)
- `NIGHT_HOUR=18` 이후 실행이면 다음날 콘티(`내일 날짜_N.json`)를 만든다(밤 제작).
- 옵션: `--now --no-upload --no-shutdown --no-fetch --no-tts --latest --episode 경로`
- 실행 cmd(**파일 내용은 ASCII 만** — 한글 있으면 cmd 가 깨짐): 루트 `지금실행`(두 시리즈) `영상만다시` `깃저장` `일정확인` `작업등록`(07:30) `메타갱신` `pc연결`(최초 1회) / 시리즈 폴더 `지금실행`·`영상만다시`(그 시리즈만, `--series rank` 또는 `issue`). 두 시리즈를 동시에 돌리지 않는다(work\ 공유) — 하나 끝나고 다음.
- 한 편만 다시: `python -X utf8 build.py render episodes\2026-09-11_1.json` (음성 재사용). 음성부터: `python -X utf8 tts.py episodes\...json` 후 `qa_voice.py`.
- 실행 중인 run_daily 가 있으면 `지금실행` 을 또 누르지 않는다(음성 폴더 충돌).

## 절대 지킬 것 (과거 사고에서 나온 규칙)
- 음량 정규화에 `loudnorm` 금지 → 짧은 클립에서 울렁임·기계음 원인. 줄별 고정 이득(평균 -19 dB, 피크 -1 dB)만.
- 한 줄은 **한 번에** 합성(` / ` → 쉼표)하고 감지된 쉼 자리에 TTS_BREATH(기본 0.3초)만 넣는다. 구간별로 따로 합성 금지(높낮이가 튐).
- 음성은 타입캐스트 웹(프로 플랜) — Claude 가 Chrome 으로 조작. **캐릭터 장운, 스마트 이모션 끔, 감정 일반, 속도 1.0x**, "문장 별로 나누기" zip → `<시리즈>\음성\<콘티이름>.zip`. 스마트 이모션을 켜면 문장마다 감정이 달라져 음높이가 튄다(9/14 이슈 편 +6반음). 새 프로젝트는 기본 캐릭터가 매번 달라 먼저 장운으로 바꾸고 대본을 넣는다.
- 쉼은 0.5초를 넘기지 않는다(MAX_GAP). 첫 줄(후킹)은 한 호흡.
- 자막은 실제 말 시작~끝에만. 파일 시작/끝 기준 금지. 0.45초 미만 조각은 합친다. 단어 중간에서 바꾸지 않는다.
- 자막 최대 2줄, 한 줄 16자. 큰 글씨는 폭 넘으면 자동 축소(단어 중간 줄바꿈 금지).
- 카드 안 큰 글씨(`.card .v`)도 카드 폭을 넘으면 자동 축소(9/16 — 이슈 편 "익숙하다"가 카드 밖으로 나감). 세 템플릿 모두 적용.
- 편별 음성 폴더(`voice_<콘티이름>`) — 1·2편이 서로 덮어쓰지 않게.
- 렌더 기본 2K 60fps(`VIDEO_FPS=60`, `VIDEO_SCALE=1.3333`). 유튜브는 60fps 가 상한이라 120fps 는 의미 없음.
- 번호 배지는 숫자만(“첫째” 같은 글자 금지), 번호와 내용을 같은 줄에 두지 않는다.
- 이모지 마크: 얼굴 이모지 금지, 원 없이, 상대전적(matchup) 장면에만 1~2개(약한 쪽 💧 정도).
- 로고끼리 겹치면 안 된다(표 칩 62px / 행 76px).
- 실행 cmd 파일은 ASCII·CRLF. 프로그램 폴더를 OneDrive/구글드라이브 동기화 폴더 안에 두지 않는다(결과물만 드라이브로).

## 콘티 규칙 (episodes JSON)
- 유튜브 제목(9/15 SEO 확정 — `docs\야구자판기_유튜브SEO_설계.md`): **`검색어 접두 | 핵심 문구 #시리즈 #구단`**. 앞 30자 안에 사람들이 실제로 치는 검색어(유튜브 자동완성 확인)를 넣고 시리즈 이름은 해시태그 자리로. 접두 — 순위: "프로야구 순위 요약" / 이슈: "<구단 정식명> 소식", 사람 중심이면 "<이름> + 검색어"(예: "하현승 일본 반응", "한일전 야구", "아시안게임 야구", "프로야구 감독 재계약") / 분석: "<구단 정식명> 부진 이유 · 전망 · 왜"("프로야구 분석"은 프로토 검색어와 섞이니 쓰지 않는다). **맨 앞에 날짜를 쓰지 않는다** — build.py 가 첫 해시태그로 올리는 날짜 `#9월15일` 을 넣는다. 사람 이름은 풀네임, 따옴표·이모지 없음, 날짜 포함 100자 이내.
- 유튜브 설명 첫 두 줄(9/15 SEO): 1줄 = 제목 검색어를 다른 말로 한 번 더 + 핵심 숫자, 2줄 = 이 영상이 답하는 질문. 그다음 친절한 문단 3~4개(선수·구단 풀네임 한 번씩), 끝은 채널 한 줄 + "재생목록: 프로야구 순위 요약 / 오늘의 야구 이슈 / 구단별 분석" + 양자택일 질문 한 줄(고정 댓글로도 단다).
- 태그(9/15 SEO) 15~22개, 앞 5개 순서: 제목 검색어 그대로 → 구단 정식명 → 구단 별칭·영문 → 사람 → 공통(프로야구, KBO, 프로야구 순위, 야구 쇼츠, 1분 야구, 야구자판기, 2026 프로야구). 자동완성에 없는 말은 넣지 않는다. 해시태그 15개 안: `#Shorts #프로야구 #KBO #야구` + 구단 + 선수 + 시리즈 + 야구자판기·야구스타그램·야구팬.
- build.py 가 `_유튜브.txt` 와 함께 **`_자막.srt`** 를 만든다(9/15) — 업로드 화면 자막 → 파일 업로드에 첨부(검색 색인용). 업로드 시간은 순위·이슈 07:30, 낮 편 12:00, 분석 20:30 으로 벌린다.
- 유튜브 설명(9/15): 나열 금지 — 처음 보는 사람에게 **친절하게 설명하듯 문단으로**(용어 뜻 포함). "📊 이 영상의 숫자" 목록·[정보] 줄은 쓰지 않는다. 해시태그는 설명 안에 넣지 말고 콘티 `youtube.hashtags`(리스트)에 — `_유튜브.txt` 가 [해시태그] 칸(인스타·틱톡 복붙용)으로 따로 쓴다(없으면 태그로 자동 생성).
- 썸네일 큰 글씨(9/15): 한 썸네일 안에서는 한 색(기존 스타일), 대신 **편마다 강조색을 바꾼다** — 이슈: 첫 편 구단색, 2·3·4편은 주황·보라·초록·파랑·빨강 순(구단색과 비슷하면 건너뜀) / 순위: 첫 편 빨강, 다음 노랑·하늘·연두·주황. `thumb.color` 로 직접 지정 가능. 썸네일 글씨(top·big)에 따옴표("") 금지 — 템플릿이 자동으로 뺀다.
- 업로드 뒤 제목·설명만 고칠 땐 재업로드 금지 → 콘티 youtube 항목 수정 후 `메타.txt` 신호(감시 중일 때) 또는 `메타갱신.cmd`.
- `lines[].narr` 나레이션, `lines[].sub` 자막(`|` 로 호흡 구간과 같은 수로 나눔, `\n` 줄바꿈), `scenes` 장면(hook/big/table/streaks/versus/matchup/need/wins/schedule/shift/rival/verdict/question), `thumb`, `youtube`, `standings`, `gameDate`.
- 장면 옵션: `wins` {rows:[{team,total,need,label}],text} 남은 경기 칸에 필요 승수 채우기 / `schedule` {title,items:[{date,teams:[a,b],place,tbd}],text} 날짜별 맞대결 / `next` {팀:상대} 또는 카드의 `next`·`nextNote` → 주인공 로고 아래 "vs 작은 로고" (hook·matchup·versus 지원) / `num` 번호 배지(big·matchup·versus).
- 나레이션: 영어 팀명은 한글 발음(기아/엘지/케이티/엔씨/에스에스지), 콤마·마침표 금지(소수점·물음표 예외), 어미 ~인데요/~에요/~거든요, “~입니다” 금지, 반올림 금지.
- 숫자 읽기: **고유어** 점·경기·게임 차·개·명·시·가지·번 (“열두 점”, “세 경기”) / **한자어** 승·패·위·이닝·회·년·월·일·억·달러·순위·연승연패·점수 (“이 승 십 패”, “삼위”). `build.py prep` 이 자동 검사한다 — 통과할 때까지 고친다.
- 마지막 질문은 **무조건 양자택일**(“삼성일까요 케이티일까요?”). 시비조 금지.
- 예측형: 변수(남은 경기 수·맞대결 수와 장소·상대전적·주말 상대와 예고 선발·AG 차출·부상 복귀)를 여러 개 같이 놓고 결론. 한 가지만 보고 결론 금지. 상대 팀 희망 요소 한 줄. 사람은 이름 명시, 왜 나오는지 인과 연결. 관계없는 팩트(감독 통산 승수 등) 금지.

## 영상 제작 3원칙 (9/15 사용자 확정 — 이 셋이 최우선)
1. **문맥의 흐름**: 한 영상 안에서 기승전결이 완벽하게 이어져야 한다. 내용과 내용 사이엔 반드시 브릿지 문장. 갑자기 다른 내용·뜬금없는 내용 금지.
2. **사진은 실물**: 웬만하면 실제 사진. 없으면 사진칸을 비워 두지 말고 텍스트만(템플릿이 photo→big 으로 자동 전환). 필요한 사진은 Claude 가 직접 기사에서 꺼내 폴더에 저장한다(링크만 주지 않는다). 워터마크 제거는 하지 않는다(저작권) — 워터마크 없는 사진 우선.
3. **기록·수치는 면밀한 팩트체크 — 가장 중요**: 사용자 이탈로 직결. 기록(최장수·최초·N년 만·통산 등)은 위키백과·KBO 공식·기사 등 **두 곳 이상에서 확인**하고, 확인 안 되면 쓰지 않는다. 사고 사례: "김응용 감독의 한 팀 10년 기록을 넘는다" → 실제는 해태 18년(1983~2000). 기사 한 줄을 읽고 넘겨짚은 결과. 비교·최상급 표현("유일", "최초", "최장")은 특히 근거 문장을 확보한 뒤에만.

## 예측 콘티 전개 틀 (9/11 확정 — "정보 나열"이 아니라 "전문가 분석")
순서는 **훅 → 현재 순위(한 장면) → 경우의 수 → 변수 2개 → "그래서 제 예측은" → 단(뒤집힐 조건) → 양자택일 질문**.
- 경우의 수는 숫자로 닫는다: "A가 남은 N경기 반타작 X승이면 B는 M경기 중 Y승 필요"(승률 직접 계산, 무승부 제외). 동률이면 규정까지: 1위는 단판 순위결정전(홈은 상대전적 우위 팀, 2021 삼성-KT 대구), 2위 이하는 상대전적→다득점→전년도 순위. 화면은 `wins` 장면(칸 채우기)으로 필요 승수를 보여준다.
- 변수는 많아야 둘, 각각 인과가 닫혀야 한다. 좋은 변수: 남은 맞대결 수·날짜·장소(`schedule` 장면), 상대전적이 만드는 타이브레이크(예: KT가 3경기 다 이겨도 9승 7패), AG 차출로 빠지는 **역할**(선발 둘+마무리 vs 야수 둘)과 그 기간 경기 수·대체 선발 횟수, 천적 전적(NC전 2승 11패)과 남은 경기 수, 상위권 상대 경기 수 차이, 부상 복귀 시점. 나쁜 변수: 하루이틀 예정 경기·선발 이름만 나열(한 번은 OK, 두 번이면 신뢰 하락), "9·10위 상대라 미끄러지면 큰일"류 개연성 없는 말, 감독 통산 승수 같은 무관 팩트.
- 정보를 다 쓰지 않는다. 흐름 하나로 이어지지 않는 팩트는 버린다.
- 데이터 출처: 순위·팀간 승패표는 KBO 공식(koreabaseball.com 팀순위 일자별 — 상대전적 표 포함), 남은 일정은 KBO 경기일정(9·10월), 우천 순연 미편성 경기는 "남은 경기 − 편성된 경기"로 센다. 뉴스는 구글.
- 화면은 자막 위 그림이 이해를 돕게: 반타작이 몇 승인지(`wins`), 맞대결 날짜(`schedule`), 두 팀이 각각 누구를 만나는지는 주인공 로고 밑에 상대 로고(`next`).

- **검증은 해시 대조.** 붙여넣고 새로고침한 뒤, 에디터 줄들과 원문 대본을 각각 `h=(h*31+charCode)>>>0` 로 돌려 값이 같은지 본다. 줄 수만 세면 못 잡는다. 다르면 줄별 해시로 어느 줄인지 찾는다.
- **내용을 갈아 끼울 때** `execCommand('selectAll')` 뒤 paste 하면 뒤에 이어붙어 중복된다. 에디터 클릭 → `ctrl+a` → `Delete` → paste 순으로.
- **크롬 탭이 뒤에 있으면**(`document.visibilityState === 'hidden'`) 다운로드 패널이 안 열리고 스크린샷도 30초 타임아웃 난다 → 사용자에게 창을 앞으로 꺼내 달라고 한다. 창 최소화(innerWidth 0)도 같다.
- 프로젝트 이름은 **JS setter** 로 ASCII(`2026-09-17_rank` 등)를 넣는다 → zip 파일명이 그대로 된다. 새 프로젝트 기본 캐릭터는 매번 다르므로(다은·문정·박창수…) 칩을 좌표로 클릭한 뒤 `'장운'` span 을 JS click.
- 받은 zip 은 **파일 수 = 줄 수 + 파일명 앞부분이 대본과 맞는지**까지 확인하고 커밋한다.

### 사진 가져오기 — tool 결과 길이 제한
- canvas `toDataURL` 결과를 반환할 때 **tool 결과가 약 26만 자에서 잘린다.** data URL 이 그보다 길면 `window.__d` 에 담아 두고 `slice(a,b)` 로 20만 자씩 나눠 여러 번 반환한 뒤 이어 붙여 디코드한다(한화 공식 투명 png 570×720 ≈ 75만 자 → 4조각).
- 다음 뉴스 원본 사진(`t1.daumcdn.net/news/…`)은 `toDataURL('image/jpeg',0.92)` 로 대개 한 번에 들어온다. 투명 배경이 필요한 구단 프로필만 png 로.
- 결과가 짧아 대화에 그대로 들어올 것 같으면 `window.__d + ' '.repeat(250000)` 로 패딩해 파일로 떨어지게 한다.
- 한화 공식 프로필 경로: 투수 `/PL/PC/PLPC01.do`, 포수 `/PL/CC/PLCC01.do`, 내야수 `/PL/IF/PLIF01.do`, 외야수 `/PL/OF/PLOF01.do`. `download/attach.do?id=` 직접 navigate 는 거부되므로 목록 페이지에서 같은 origin canvas 로 뽑는다.
- 구단 제공 사진이 실린 다음 뉴스 원본은 워터마크가 없어 써도 된다(alt 에 "○○ 제공" 표기 확인).
