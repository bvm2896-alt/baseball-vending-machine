## 1. 음성 속도와 구독 멘트 (9/24 사용자 "말도 너무 느리고 말 사이 텀도 너무 길어" / "구독 멘트까지 빨라졌다 — 다음 영상부터 고려해서")

- **구독 멘트는 빠르게 하지 않는다.** 본문 줄은 1.2배로 뽑고, "채널 구독하고 매일 야구 이슈 받아보세요" 는 **따로 1.0배 · 감정 '기쁨'** 으로 한 번 뽑아서 마지막 질문 뒤에 **0.5초 쉬고** 이어 붙인다(질문과 구독 멘트 사이 쉼도 늘리거나 줄이지 않는다).

  - 9/24 에 뽑은 구독 멘트 음성(1.0배·기쁨): `제목_없음 (14).zip` 의 16번째 파일. 다음에도 재사용 가능.
- **쉼 기준(9/24 적용값)**: 문장 안 쉼 약 0.14초(+호흡 자리 TTS_BREATH 0.1), 줄 사이 쉼은 콘티 `"gapScale": 0.75`(build.py 가 설정.txt GAP_SCALE 보다 우선). 1.2배로 녹음하면 문장 안 쉼은 따로 줄이지 않아도 된다 — 뽑아 보고 길면 줄인다.

## 2. 숫자 읽기 (9/24 사용자 확정 — 공통규칙 §4 의 '점은 고유어' 를 바꾼다)
- **점수·점·실점·득점·타점·안타 수는 전부 한자어**: 삼십육 점 넣고 일 점만, 삼십삼 점 넣고 삼 점만, 오 점 차, 사 타점, 이백이 안타, 오 회에 이 점 / 육 회에 일 점.
- **게임 차는 고유어**: 아홉 게임 차(구 게임 차 ✗ — 사용자 지적).
- 경기 수·명·살·시·번은 고유어 그대로: 열두 경기, 스물네 명, 스무 살, 여섯 시 반, 두 번.
- 승·패·위·이닝·회·년·월·일·연패는 한자어 그대로.
- **점수 순서는 화면과 같게**: 화면이 `한국 5-0 대만` 이면 나레이션도 "한국에 오 대 영으로 졌어요"(대만 쪽에서 본 "영 대 오" ✗).

## 3. 끊어 읽기 (9/24 "23일대전한화전 한 번에 말하는 게 사람 같냐")
- **타입캐스트는 쉼표에서만 쉰다.** ` / ` 는 쉼표로 바뀌지만, 그 사이에 명사가 줄지어 있으면 한 번에 붙여 읽는다.
- 날짜·장소·상대, 이름 나열, 시각·장소 사이에는 **나레이션에 쉼표를 넣는다**: "이십삼 일, 대전, 한화전" / "한국, 대만, 일본, 중국" / "도요타, 도쿄가스" / "김도영, 소형준, 문현빈도" / "이십오 일, 저녁 여섯 시 반, 도요하시예요".
- 자막(`sub`)에는 쉼표를 넣지 않는다. 생성기 `L()` 은 쉼표를 자막에 옮기므로 FIX 로 자막을 따로 적는다(`gen_0924.py` FIX 참고).
- 대본 검수 때 호흡마다 소리 내어 읽어 보고, 사람이 끊어 말할 자리에 쉼표가 있는지 본다.

## 4. 화면
- **줄바꿈(9/24 "대만 vs 중/국 — 줄바꿈을 잘 해야 먹고산다")**: 세 템플릿 `*{word-break:keep-all}` — 낱말 가운데서 절대 안 끊긴다. `cards` 이름에 "A vs B" 가 있으면 자동으로 `A / vs / B` 세 줄. 새 콘티는 미리보기 전 장면을 찍고 `scratchpad/shotall.js`(낱말 끊김·화면 밖 글자 자동 검사)로 확인한 뒤 넘긴다.
- **순위 썸네일에도 사진**(`thumb.html` 사진형, `thumb.img`): 팀 색 배경 + 인물 누끼 사진 + 작은 로고 칩. 큰 글씨는 **흰 글씨 + 마지막 줄 노란 띠(`bigStyle:"box"`, 기본)**. 주황 배경 위 빨간 글씨는 뭉개져서 금지.
- 이슈 틀(`thumb_issue.html`)을 순위 편에 빌려 쓰지 않는다(사용자 "왜 템플릿이 야구이슈 버전이냐").
- 한화 공식 사진은 `hanwhaeagles.co.kr/PL/OF/PLOF01.do` 등에서 `download/attach.do?id=` 가 파일로 **바로 다운로드된다**(9/24 문현빈 — 허락 없이 받아 버림). 이 주소로 navigate 하지 말고, 먼저 사용자에게 받아도 되는지 묻는다.

## 5. 파일 이름·구독 멘트 위치
- 결과물 이름 = `<슬롯>_<주제>` (`이슈5_한일전미리보기.mp4`). 콘티 `"topic"` → 없으면 썸네일 큰 글씨 첫 줄 → 없으면 팀 이름(`build.py topic_label`).
- 구독 멘트는 **맨 뒤 유지**(첫 1~2초 이탈 때문에 앞에 두지 않는다). 끝까지 보는 비율이 너무 낮으면 핵심 내용 직후로 옮기는 걸 스튜디오 수치로 판단.

## 6. 일하는 방식 (9/24 사용자 강한 지적)
- **질문을 받으면 먼저 답하고, 만들기는 답을 받은 뒤에.** 질문을 두고 녹음·제작부터 하면 크레딧이 샌다("물어보잖아, 왜 자꾸 만들기를 먼저 해").
- 판단이 애매한 발음·표기는 확정하지 말고 "확실한 것 / 판단 부탁" 으로 나눠 보여 준다.
- 올린 편은 바로 콘티 `"done": true`.
