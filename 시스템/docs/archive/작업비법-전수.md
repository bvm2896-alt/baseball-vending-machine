## 1. PC 와 클라우드 오가기 (이 채팅엔 PC 셸이 없었다 — 파일 올리기/내리기만)
- **필요한 파일만 올린다**: `device_stage_files` 는 파일 단위. 폴더 전체를 올리지 말고 `device_list_dir` 로 이름·크기·수정시각(mtimeMs)을 먼저 보고 고른다.
- 올린 파일은 `/mnt/user-data/uploads/야구자판기/…` 에 **읽기 전용**으로 생긴다 → 고칠 파일은 작업 폴더로 복사해서 고친다.
- **올린 지 오래된 파일은 다시 본다**: 다른 채팅이 같은 PC 파일을 고칠 수 있다(이 채팅에서도 template·build.py 를 다른 세션이 바꿈). 고치기 직전 `device_list_dir` 로 mtime 을 다시 확인.
- **내려 쓸 때(commit)**: 완성 파일을 `/mnt/user-data/outputs/<작업명>/` 에 두고 `device_commit_files` 의 `stagedPath` 로. 기존 파일을 덮을 땐 **반드시 `expectedMtimeMs`**(마지막으로 본 mtime) — 다른 세션이 그 사이 고쳤으면 거절돼서 남의 작업을 안 덮는다. 새 파일은 생략.
- **내린 뒤 확인**: 같은 경로를 다시 stage 해서 `cmp` 로 바이트 비교. jpg/png 는 전달 과정에서 메타데이터가 바뀌어 바이트가 다를 수 있으니 **픽셀 비교**(numpy 평균 차이 0)로 확인.
- **경로 오타 주의**: 한글 경로를 유니코드 이스케이프로 쓰다 한 글자 틀리면(외야→외씁, 손아섭→손아성) "없음"으로 거절된다. 거절 메시지의 경로를 보고 바로 고친다.
- Google Drive(`H:\내 드라이브\야구자판기_영상확인\`)도 연결 폴더라 영상 결과물 폴더를 직접 보고 썸네일을 바로 넣을 수 있다.

## 2. 롱폼 → 컷 쇼츠 만들기
**생성기 패턴**(최신 예: `시스템\tools\gen_1018_gg_cuts.py`, 앞선 예 `gen_1020_cuts.py`)
- `OLD(i)` = 롱폼 i번 줄과 그 장면을 그대로(음성도 롱폼 것 재사용), `OLD(i, 장면)` = 장면만 바꿈.
- `NEW(말, 자막, 장면)` = 새 줄(훅·질문 등, 이것만 새로 합성). 자막은 `|` 로 호흡 나눔, 16자 줄바꿈 자동, `까요/나요` 끝엔 `?` 자동.
- `ppx(i, drop=(), **바꿀것)` = 롱폼 장면을 복사하되 chain/cont 를 떼고 고쳐 씀.
- `Qs(…)` = 마지막 질문 화면(faces 는 원 안 → 프로필 사진만, 프로필 없는 선수가 끼면 `logos` 로).
- `POINT()` = "<롱폼> 전체는 하단 관련 영상에" + 롱폼 썸네일 사진(`상황별/썸네일_롱폼N_…`), `CTA()` = 구독 멘트(고정 음성, 합성 안 함).
- 콘티 머리: `voiceFrom: {ep: '<롱폼 파일명>', lines: [롱폼 줄 번호 또는 None]}` 이 롱폼 음성 재사용의 핵심.
- **cont(이어짐) 규칙**: 앞 장면이 같은 chain 일 때만 cont 를 남긴다(롱폼에서 사이 줄을 빼도 같은 묶음이면 이어짐). 같은 장면을 훅과 본문에 두 번 쓰면 둘째 장면에 `cont=True` 를 줘야 다시 튀어나오지 않는다.
- **thumb 필드는 필수**(10/21 실수: 빼먹어서 썸네일 없이 영상이 나옴). 생성기에서 THUMBS 표로 같이 쓴다.
- 편마다 챕터 하나, 4~6편, 새 3초 훅을 맨 앞, 결론을 마지막 말로, 1:20 이하, 롱폼 연결어 금지, 제목 앞은 그 챕터 고유명사(편마다 검색어 다르게), #Shorts 맨 앞.

**길이를 정확히 재는 법**: 추정(글자×0.14초) 말고 **롱폼 음성 zip 을 올려 실제 길이로**. `야구롱폼\음성\<롱폼>_음성.zip` 안 `NN.mp3` 를 ffprobe 로 재서 OLD 줄은 실제 초, NEW 줄은 (롱폼 전체 초 ÷ 전체 글자) × 글자, 줄 사이 0.45×gapScale 를 더한다. 이번엔 47~61초로 나왔다.

**파일 이름으로 충돌 막기**: long_build.py `--cuts` 는 인자가 없으면 '가장 최근 날짜' 컷만 만든다. 그래서 지난 롱폼의 컷은 **롱폼 날짜로 이름**(`2026-10-18_롱폼컷1~6.json`)을 붙여 날마다 만드는 컷과 안 섞이게 하고, 전용 버튼은 `python -X utf8 tools\long_build.py --cuts 2026-10-18_롱폼컷` (인자가 파일 이름에 포함된 것만 고름). 버튼 파일은 기존 `롱폼_숏츠만들기.cmd` 를 그대로 베끼고(CRLF, `chcp 65001`, rem 은 영어) 마지막 줄 인자만 바꾼다.
- 콘티 지문(sha1)이 바뀌면 long_build 가 다시 만든다 → 영상이 이미 나온 뒤 썸네일만 바꿀 땐 **썸네일 jpg 를 Drive 결과 폴더에 같은 이름(`롱폼컷N_<topic>_썸네일.jpg`)으로 직접 넣고** 사용자에게 "다시 안 눌러도 된다"고 말한다.

## 3. 미리보기 — PC 렌더 전에 내가 먼저 본다
- **거울 폴더**: 올린 폴더는 읽기 전용이라 작업 폴더에 `시스템`(episodes·tools·work 는 복사, 나머지는 링크) + `폰트` 링크 + `선수이미지\<폴더>`(실제 폴더 + 파일마다 링크) 를 만든다. 명령은 `claude/사진-쓰는법-인수인계.md` 4장. build.py 가 `data/rank_latest.json` 을 찾으니 복사해 둔다.
- **장면 끝 프레임**: `PV_SEC=4 python3 -X utf8 tools/preview.py episodes/X.json template_long_v.html out.html` → playwright 로 줄마다 `render(4*(i+1)-0.05)` 캡처(줄 끝 = 애니메이션 다 끝난 모습). 크롬은 `/opt/pw-browsers/chromium`, 전역 playwright 는 `require(npm root -g + '/playwright')`.
- **한 장 판으로 본다**: 편마다 캡처를 8칸씩 붙인 판(270×480)을 Read 로 본다 — 빈 장면·잘린 글·겹침·이름 틀림을 한 번에.
- 미리보기에서만 생기는 것: 로고 파일(KBO_logos)을 안 올리면 로고 자리가 빈다(PC 에선 나옴). 자막은 첫 호흡만 보인다.
- 템플릿이 장면 종류를 지원하는지 먼저 grep(예: `hold`, `vhide`, `facegrid` 의 profile·logos 처리). 세로 템플릿(template_long_v.html)은 가로와 따로 고쳐지므로 둘 다 확인.

## 4. 썸네일
- **세로 컷 썸네일 틀** = 10/21 컷들과 같은 `thumb_issue.html` 사진+큰 제목형: `{"halo":18,"cutout":true,"cutoutLift":180,"cutoutOverlap":330,"cutoutFade":0.62,"ph":1000,"logos":false,"noPills":true,"top":"","perLine":true,"img":…,"big":"줄1\n줄2","color":"#…","teams":[…]}`. 카드 jpg 는 `cutoutCrop` 0.85, 누끼 png 는 0.6, 그룹 누끼(1080×1475)는 0.8.
- 렌더: `EP = build.load_episode(p); EP['thumb']=…; build.make_thumb(EP, out)` (`CHROME_PATH=/opt/pw-browsers/chromium NODE_PATH=$(npm root -g)`).
- **인물 = 제목·주제의 사람 전원**(10/21 "외야면 외야 후보 4명 넣고"). 여러 명은 누끼를 합친다(5장).
- **눈 검사 순서**: ① 사용자가 보는 크기(360×640)로 6편을 한 판에 ② 얼굴만 원본 크기로 잘라 흐림·가림 확인 ③ 최근 컨펌·직전 편 썸네일 판(`ref`)과 나란히 → 같은 사진·같은 색 반복 피함 ④ 손·팔이 사진 칸 끝에서 잘렸는지(오스틴 사례) ⑤ 팔이 옆 사람 얼굴을 가리는지(최형우 팔→강백호 턱 사례).
- **흐림 판단**: 원본 폭(px) ÷ 놓일 폭 → 1.25배 넘으면 흐리다. 허인서 396px 사진은 2.3배라 흐림 → 사용자에게 사진 요청으로 남김.
- **얼굴 가림 사례로 교체한 것**: 구자욱 세리머니(입가 가드가 얼굴 아래를 가림)·연합뉴스 김도영(헬멧 챙이 눈을 가림) → 다른 사진.
- 16:9 롱폼 포스터용 관문(`thumb_gate.py`)은 세로 사진+제목형엔 맞지 않는다 → 이 형식은 눈 검사로 끝내고, 그렇게 했다고 사용자에게 말한다.
- 보여 줄 때: 6편 한 판 이미지를 SendUserFile 로, 표로 사진·큰 글씨, 남은 약점(흐림·고개 위)을 숨기지 않고 적는다. 고친 판을 다시 보낼 땐 최종본인지 확인(보낸 뒤 고친 편이 있으면 판을 다시 만들어 다시 보냄).

## 5. 누끼와 여러 명 합치기
- **누끼 따기**: `tools/isnet_cutout.py`(ISNet 1024px, u2net 320px 의 `cutout.py` 보다 깨끗함). 모델은 GitHub 에서 받는다(사진 문서 3장).
- **누끼 정리**: 옆 사람 손이 반투명으로 남으면 알파 0.45 미만을 0 으로, 그래도 남으면 영역을 지운다 — 단 **몸이 직선으로 잘리면 그 사진은 포기**(강백호 환대 사례). 직선으로 잘린 끝은 앞사람 뒤·제목 뒤·캔버스 밖으로만 둔다.
- **머리 위치 재기**: 누끼마다 위쪽 절반을 잘라 100px 격자와 원본 좌표 숫자를 그린 판을 만들어 Read 로 보고 헬멧 왼쪽·오른쪽 x, 머리 중심 (x,y)를 적는다(OpenCV 5 에는 얼굴 검출 Haar 가 없음).
- **합치기**: `tools/group_compose.py 배치.json` — `head:[헬멧왼x, 헬멧오른x, 중심x, 중심y]`, `hw`(놓일 헬멧 폭), `x,y`(놓일 머리 중심), `z`. 로그의 scale 이 1.25 이하인지 본다.
- **자리 정하기**: 4명 = 뒤 가운데 1명(팔 든 사람이 위쪽 테두리를 채움) + 앞줄 3명, 앞줄 머리 꼭대기는 뒷사람 턱보다 60px 이상 아래. 2명 대결 = 제목 순서대로 왼쪽·오른쪽, 바깥으로 뻗은 팔은 바깥쪽 자리, 안쪽으로 뻗은 팔은 뒷사람(z 작게) 것이어야 앞사람 몸 뒤로 숨는다. 든 손이 캔버스 위로 나가면 사람을 내린다.
- 만든 그룹·누끼는 **PC `선수이미지\누끼\` 에 커밋**(다음 채팅이 은행에서 바로 씀).
